STRAY FREQUENCY — CODE/REPOSITORY SECURITY PASS

Included:
1. .gitignore
   - ignores node_modules, dist, local environment files, logs and editor noise.
   - IMPORTANT: .gitignore does not remove files that are already tracked by Git.
     The existing tracked node_modules/ and dist/ directories still need to be
     deleted from the repository once. Do not delete package-lock.json.

2. .github/workflows/deploy.yml
   - switches deployment from `npm install` to reproducible `npm ci`.
   - enables the npm cache.
   - audits production dependencies for HIGH/CRITICAL vulnerabilities before deploy.
   - keeps the build/deploy permissions narrowly scoped.

3. .github/dependabot.yml
   - weekly npm dependency checks.
   - weekly GitHub Actions dependency checks.
   - groups routine npm minor/patch updates to reduce PR noise.

4. SRC/ui/html.ts
   - documents the existing escaping helper as suitable for quoted attributes as
     well as text content, and records the preferred DOM/textContent approach.

NOT INCLUDED YET:
- A strict Content-Security-Policy. The current UI contains inline style
  attributes (for activity anchors, maps and progress widths), so a useful strict
  CSP should be introduced deliberately rather than adding a policy that either
  breaks the game or permits unsafe-inline and provides little value.
- Hostile-client Supabase integration tests. Those deserve their own test harness.

ONE-TIME REPOSITORY CLEANUP:
After these files are uploaded, remove the tracked `node_modules/` and `dist/`
directories from GitHub. Keep `package-lock.json`. Future installs/builds recreate
those directories, and .gitignore prevents them being committed again.
